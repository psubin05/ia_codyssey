## 확인 근거와 남은 사항

- 사용자 브라우저 확인 완료 보고를 반영했다. 항목별 실행 내역이나 화면 캡처는 전달받지 않았으며, AI 모의 검사와 구분했다.
- 기능 추가 전 원본 직접 점검 여부는 현재 대화에서 확인되지 않는다. 원본 보존과 SHA-256 일치는 확인했다.
- 모델명은 사용자가 알려 준 표기를 그대로 기록했다. 화면의 모델명 표기를 AI가 별도로 확인한 것은 아니다.
- 코드·기록 파일은 준비됐으나, 과제의 이미지 제출 요건까지 모두 충족했다고 단정하지 않는다.
- GitHub 제출 대상: `psubin05/ia_codyssey` 저장소의 `main` 브랜치, `1-4` 폴더. 업로드 결과는 Git 커밋과 원격 브랜치 반영 여부로 확인한다.

위 문구는 평가 피드백을 받아 정리한 재사용 안내이며, 당시 사용자가 그대로 입력한 대화로 소급하지 않는다. 실제 대화는 `codex 대화.md`에 기록했다. 실제 작업에서는 사용자가 원본을 지정했고 AI가 앞서 읽은 기획서에 검색 기준을 추가한 뒤 구현했다. 완성 기준을 추가한 기획서를 사용자가 별도로 재첨부한 이력은 없다.

## 오류 시 수정 및 원본 복귀 기준

1. 받은 파일은 원본을 덮어쓰지 않고 별도 이름으로 보존한다. 기획서의 기존 기준과 검색 기준을 처음부터 확인한다.
2. 기존 기능은 정상이고 새 검색 기능만 틀렸다면, 행동·기대 결과·실제 결과를 기록해 수정 요청한다. 받은 HTML은 `영화_기능추가_수정1.html`, 다음은 `_수정2.html`처럼 저장하고 전체 기준을 다시 확인한다.
3. 기존 이동·추가·저장·초기화 등 원래 기능이 망가졌다면 해당 파일의 수정 요청을 즉시 멈춘다. 문제 파일도 지우거나 덮어쓰지 않는다.
4. 보관한 `영화_원본.html`을 기준으로 새 대화를 시작한다. 원본과 검색 기준을 포함한 `기획서.md`를 첨부하고 위 요청 문구로 다시 요청한다. 복귀 후 받은 파일도 새 이름으로 보존하고 전체 기준을 다시 확인한다.
5. 이번 작업에서는 오류가 보고되지 않아 2~4의 실행 조건이 발생하지 않았다. 수정 이력을 만들기 위한 복제 파일은 생성하지 않는다.

과제는 “새 기능이 틀리면” 수정본을 만들고 “원래 기능이 망가졌으면” 원본으로 돌아가도록 정한다. 제공된 코랩 리포트 7장 역시 조건에 해당하는 일이 없으면 해당 항목에 체크하도록 안내한다. 따라서 수정본·복귀 이력 부재만으로 미실행 실패라고 판단하기보다 조건 발생 여부와 기록을 함께 확인해야 한다.
