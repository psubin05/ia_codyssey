# 제작·검증 기록: 포근한 하루 — 하루 일정 관리

## 제작 목적과 비교 기준

오늘 해야 할 일을 먼저 확인하고, 중요도가 높은 일부터 처리할 수 있는 일정 관리 페이지를 제작했다. `기획서.md`의 필수 기능과 완료 기준을 바탕으로 두 결과를 비교했다.

비교 기준은 일정 추가·정렬·완료 상태 저장·빈 제목 입력 처리와 화면 구성이다. 화면은 기획서에서 정한 크림색·살구색·갈색의 포근한 분위기, 오늘 할 일의 강조, 지난 미완료와 달력의 배치, 일정 정보의 표시 방식을 살펴봤다.

## 두 AI와 전달 요청

- AI A: OpenAI Codex / GPT-6.1 Sol Light (사용자 확인)
- AI B: Google Gemini / 3.6 Flash (사용자 확인)
- 제작 기준 기획서: `기획서.md`
- 공통 요청 원문: `동일요청.md`
- Codex는 위 기획서와 공통 요청을 기준으로 제작했다. Gemini에도 동일한 기획서와 요청 전체를 전달했는지는 제출 전 확인이 필요하다.

### 공통 요청

> 첨부한 기획서.md에 따라 HTML 페이지를 만들어 줘.
>
> - HTML 파일 1개 안에 CSS와 필요한 JavaScript를 모두 포함해 줘.
> - 파일을 브라우저에서 직접 열어 사용할 수 있게 해 줘.
> - 기획서의 필수 기능, 화면 구성과 동작, 완료 기준을 구현해 줘.
> - 화면 문구는 한국어로 작성해 줘.
> - 로그인, API 키, 서버가 필요한 기능과 챗봇·AI 기능은 넣지 마.
> - 기획서의 추가 기능은 이번 구현에서 제외해 줘.
> - 외부 사진·글꼴·라이브러리 없이 시스템 글꼴과 텍스트 기호를 사용해 줘.
> - 실제 개인정보나 사용자 일정은 기본 데이터에 넣지 마.
> - 완전한 HTML 코드를 처음부터 끝까지 제공해 줘.
>
> 두 AI에는 이 요청과 같은 기획서를 그대로 전달한다. 이 문장을 포함하여 요청 전체를 동일하게 사용한다.

### 선택한 결과물과 근거

- 선택한 결과물: **Codex — `포근한하루_v1.html`**
- 직접 판단한 이유: **“UI가 더 친근해서 사용하기 좋다.”**
- 위 판단을 화면 차이와 연결해 정리한 선택 근거 초안:

> 두 결과 모두 일정 정렬, 완료 상태 저장, 빈 제목 입력 처리 테스트에서 예상대로 동작했으며, 저는 UI가 더 친근하고 사용하기 좋게 느껴진 Codex 결과를 선택했습니다.
> Codex는 오늘 할 일을 넓은 상단 영역에 강조하고 지난 미완료를 그 아래에 배치해, ‘오늘 해야 할 일을 먼저 확인한다’는 기획 의도를 잘 드러냅니다.
> 크림색·살구색·갈색의 포근한 분위기와 함께 일정마다 예정일과 중요도 숫자를 표시하는 구성도 선택 이유를 뒷받침합니다.

선택 근거 초안은 사용자가 밝힌 선호와 확인 가능한 화면 구성에 근거해 AI가 문장을 정리했다. 제출 전 자신의 생각과 맞는지 읽고 확정한다. 작업 속도, 장기간 사용 만족도, 모든 기능의 우수성을 확인했다는 의미는 아니다.

### 선택하지 않은 결과의 설명

Gemini 결과는 상단에서 오늘 할 일과 지난 미완료를 나란히 보여 주고, 하단에서는 달력 옆에 입력 폼과 선택 날짜 목록을 배치한다. 별을 클릭해 중요도를 선택하며, 수정·삭제는 아이콘 버튼으로 제공한다. 두 결과 모두 사용자가 수행한 세 기능 테스트를 통과했다. 최종 선택은 기능 오류의 유무보다는 사용자가 느낀 친근함과 기획 의도에 맞는 화면 구성을 중심으로 이루어졌다.

선택하지 않은 HTML은 `비교자료/포근한하루_Gemini_원본.html`에 보관하며 제출 파일에는 포함하지 않는다. 위 설명으로 비교 결과를 남긴다.

## 선택한 HTML 테스트 기록

- 대상 파일: `포근한하루_v1.html`
- 수행자: 사용자 본인
- 기록 방식: 사용자가 두 HTML 모두 아래 세 작업에서 예상대로 동작했다고 보고한 내용을 AI가 정리했다.
- 테스트 환경 (브라우저·화면 크기·배율): 미기록

| 번호 | 테스트 내용 | 예상 결과 | 실제 결과 |
| --- | --- | --- | --- |
| 1 | 같은 날짜에 중요도가 다른 일정을 추가하고 목록의 정렬 순서를 확인한다. | 중요도가 높은 일정부터 표시된다. | 중요도가 높은 일정부터 표시되어 예상과 일치했다. |
| 2 | 일정 하나를 완료 체크한 뒤 새로고침하고 완료 상태가 유지되는지 확인한다. | 새로고침 후에도 해당 일정의 완료 상태가 유지된다. | 새로고침 후에도 완료 상태가 유지되어 예상과 일치했다. |
| 3 — 빈 입력값 조건 | 제목을 비우고 저장 버튼을 눌러 안내 표시와 일정 추가 여부를 확인한다. | 제목 입력 안내가 표시되고 일정은 추가되지 않는다. | 입력 안내가 표시됐고 일정은 추가되지 않아 예상과 일치했다. |

세 번째 테스트는 정상 입력 대신 빈 제목을 사용한 조건 변경 테스트다. 수행한 세 테스트에서는 예상과 다른 결과가 보고되지 않았다. 같은 중요도에서의 시간별 정렬, 불완전한 시간 입력, 삭제 확인 취소, 자정 경과, 저장소 사용 불가, 좁은 화면 등은 이번 기록만으로 검증 완료라고 판단하지 않는다.

## 코드 검토 참고 사항

아래 내용은 실행 테스트와 구분한 코드 검토 메모이며, 이번 미션에서는 원본을 수정하지 않았다.

- Gemini는 넓은 화면에서 지난 미완료를 오늘 할 일 옆에 배치해, 기획서의 ‘오늘 할 일 아래’ 배치와 차이가 있다.
- Gemini의 일반 일정 카드에는 예정일이 없고 중요도 숫자는 툴팁으로 제공된다. 기획서의 목록 정보 표시와 비교할 부분이다.
- Gemini의 제출 함수는 제목과 날짜의 빈 값 여부를 검사하지만 시간 입력의 `validity.badInput` 등을 별도로 검사하지 않는다. 불완전한 시간 입력이 실제 브라우저에서 어떻게 처리되는지는 추가 테스트가 필요하다. 빈 제목 테스트 통과만으로 날짜·시간 검증 전체가 통과했다고 볼 수는 없다.
